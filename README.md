# Quid Pro Quo — учебный кредитный кабинет

Два режима в одном веб-приложении: предприниматель подбирает кредит и подаёт заявку; сотрудник банка видит общую очередь, запрашивает уточнения, предлагает условия и меняет решение. Изменения доступны клиенту при обновлении его заявки. Это прототип для кейса чемпионата, без реального скоринга и интеграций Альфа-Банка.

**Общая онлайн-версия с базой заявок:** https://artemev009.github.io/quid-pro-quo-mvp/ — код банка передаёт владелец проекта. Интерфейс размещён на GitHub Pages, а сервер заявок и общая база данных работают на Sites; исходники API приведены в `cloud-source/`.

## Быстрый запуск

Нужен Node.js 22+; дополнительных пакетов нет.

```powershell
node server.js
```

Откройте http://localhost:8080. Второй вариант: `docker compose up --build` и тот же адрес. Данные заявок лежат в `data/applications.json`; Docker хранит их в отдельном томе.

## Как показать команде

1. В режиме клиента нажмите «Подобрать кредит», выберите цель, сумму и срок. Заполните форму **вымышленными данными** и отправьте.
2. Нажмите «Кабинет банка →». Демо-код сотрудника: `bank-demo-2026`. Банк увидит заявку даже в другом браузере, если он подключён к тому же серверу.
3. Откройте заявку, выберите «Запросить сведения», напишите вопрос и сохраните. Вернитесь к клиенту → «Моя заявка» → «Обновить»: появится запрос. Клиент может ответить.
4. В кабинете банка обновите очередь: ответ появится в карточке. Отправьте предложение с суммой, сроком и ставкой либо одобрите/отклоните заявку. Клиент увидит новое состояние.

Для своего демо-кода задайте `BANK_DEMO_PIN` перед запуском. Например, в PowerShell: `$env:BANK_DEMO_PIN="мой-код"; node server.js`. Код — простая защита демонстрации, а не полноценная банковская авторизация.

## Что сделано

- HTTP API для создания заявки, просмотра своей заявки, ответа клиента, очереди банка и изменения её статуса.
- Общий серверный JSON-файл с историей событий; браузер хранит только идентификатор заявки и секрет доступа к ней.
- Проверка вводимых значений и доступа к банковским действиям.
- Docker-образ и постоянный том для заявок.

Это учебное приложение: не вводите реальные персональные данные. Для настоящего банковского продукта потребуются проверенная аутентификация сотрудников и клиентов, аудит, согласия и интеграции банка. GitHub Pages поддерживает только статические файлы, поэтому API и общая база размещены отдельно.
